03

許可されても、実行できない？

RAR版でAの更新が成功したら、提供側でAを「編集禁止」にして、同じトークンでもう一度更新してください。

提供側のポリシー

「編集禁止の文書は更新しない」。RARとは別に、OPAが判定します。

このスイッチはハンズオン専用の管理操作です。トークンは変更・再発行しません。チェックを外すと元に戻ります。

もう一歩：未対応の条件を要求すると？

このデモで定義していない項目をRARに追加します。認可サーバーは条件を無視して発行せず、invalid_authorization_detailsで拒否します。

未対応の条件を送る
持ち帰ること

RARは、細かなアクセス要求を
OAuthの共通形式で伝える。

JWTには以前から独自情報を載せられます。RARが標準化するのは、詳細なアクセスの要求と承認結果をやり取りする方法です。条件の意味は業務ごとに定義し、APIとOPAが実行時に強制します。

このデモの文書用typeは独自の定義です。RARを載せるだけで自動的に安全になるわけではありません。
